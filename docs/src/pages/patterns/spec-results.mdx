```tsx
import { SpecResults } from '@cypress-design/react-spec-results'

export default () => (
  <SpecResults
    results={{ failed: 1, passed: 18, skipped: 1, running: 2, queued: 3 }}
    onCancel={() => {}}
  />
)
```

## When to use it

SpecResults sits at the top of a run's detail tabs and answers "how is this run going?" before anyone scrolls or opens the Specs tab. It replaces the old `NoticeSpecsQueuedRunning` well pattern in Cypress Cloud. It is not a general-purpose progress bar — the statuses, their order, and the copy are fixed to Cypress Cloud's spec lifecycle.

## States

Everything renders off `results` and whether `onCancel` is passed — there's no separate `state` prop.

- **Indeterminate** — every count is zero (no spec isolation yet, or nothing claimed). Falls back to a single "Testing in progress" pill and a fully animated bar.
- **Running** — `running` or `queued` is above zero. A trailing pill sums both as "N specs remaining." Queued specs never get a pill of their own.
- **Scheduled to complete** — every group has finished but the project's completion delay is still holding the run open. The trailing pill swaps a spec count for a countdown ("60s remaining") and links to Project Settings instead of the Specs tab. Don't pass `onCancel` here — cancelling would stamp a finished run as cancelled.
- **Complete** — nothing running or queued, no `scheduledToComplete`. The remaining pill and Cancel button both disappear.

## Props

| Prop                  | Type               | Default   | Description                                                                                                                          |
| --------------------- | ------------------ | --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `results`             | `SpecResultCounts` | required  | `{ failed?, errored?, passed?, skipped?, running?, queued? }` — plain numbers. Omitted keys are zero.                                     |
| `onCancel`            | `() => void`       | —         | Renders the Cancel run button and fires on click. Omit once the run completes.                                                            |
| `scheduledToComplete` | `string`           | —         | Remaining delay, e.g. `"60s"`. Shown instead of a spec count on the trailing pill when nothing is running or queued.                      |
| `label`               | `string`           | `"specs"` | Noun appended to each pill (`"28 passed specs"`). Singular drops the trailing `"s"`. Pass `""` to drop it entirely.                       |

The caller folds Cloud's `RunInstanceStatusEnum` onto the six `results` keys — `TIMEDOUT` → `errored`, `NOTESTS`/`CANCELLED` → `skipped`, `UNCLAIMED` → `queued`. The component has no knowledge of that enum.

## Interaction

Every pill (except the scheduled-to-complete pill) is a plain relative `<a href="../specs?specStatus=[...]">` — no router dependency, works from any tab under `/projects/:id/runs/:id/*`. On hover, a pill's text and icon take on the status's own hue rather than a generic link color, so the hover reads as "go to this status." Below Tailwind's `sm` breakpoint the pills and Cancel button stack vertically and left-align.
